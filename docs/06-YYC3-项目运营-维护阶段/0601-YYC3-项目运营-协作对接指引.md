## 四、协作卡点与优化

| 卡点 | 根因 | 影响 | 优化动作 |
| ---- | ---- | ---- | -------- |
| 无 Git | 未初始化版本控制 | 改动不可追溯 | 立即建库并冻结基线 |
| 数据源分歧 | Mongo/SQLite/Mock 并存 | 联调反复 | 架构评审定唯一事实源 |
| 资产路径不一致 | 设计与代码各写各的 | 图片/音频 404 | 以 0801 为唯一契约 |
| 空壳模块 | 承诺超前于实现 | 期望落差 | 明确“规划中”并从验收移除 |
| 文档冲突 | 多份总结并存 | 决策依据混乱 | 以 docs/README.md 为唯一入口 |
| 环境不一致 | 本地/容器混用 | “我这能跑” | 一键 compose + `.env.example` |

## 五、需求变更流程

```text
提出 → 产品评估价值 → 技术评估影响（工期/风险/兼容）
     → 变更评审（负责人审批）
     → 更新 0101 范围 / 0301 清单 / 0402 用例
     → 排期实施 → 验证 → 发布 → 通知
```

**原则**：无评审不排期；无文档不交付；无回滚方案不上线。

---

## 六、问题上报路径

```text
发现 → 登记 Issue（现象 / 复现 / 环境 / 影响 / 期望）
     → 分级：
        P0 服务不可用/数据丢失/密钥泄露 → 5 min 通报，30 min 响应
        P1 核心功能受损             → 15 min 通报，2 h 响应
        P2 一般缺陷                 → 当日登记，8 h 响应
        P3 优化建议                 → 进入迭代池
     → 修复 → 回归 → 关闭 → 复盘（P0/P1 必做）
```

**升级机制**：超时未响应自动升级至项目负责人；跨团队阻塞由项目负责人协调。
