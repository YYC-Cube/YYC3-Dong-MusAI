## 二、容器化方案（建议）

### 2.1 前端多阶段构建

```dockerfile
# web_app/Dockerfile（建议替换现有单阶段写法）
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM nginx:1.27-alpine
COPY --from=build /app/build /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
HEALTHCHECK CMD wget -qO- http://localhost/ >/dev/null || exit 1
```

### 2.2 编排修正

现有 [docker-compose.yml](../../docker-compose.yml) 引用了不存在的 `./ai_services/lyrics_generator`，会导致构建失败。修正原则：

1. 删除不存在服务，或补齐目录后再启用。
2. 为 `api` 增加 `healthcheck` 与 `restart: unless-stopped`。
3. 前端改为构建产物 + Nginx，不使用 CRA dev server。
4. 数据库使用具名卷持久化。

```yaml
services:
  web:
    build: ./web_app
    ports: ["8080:80"]
    depends_on: [api]
  api:
    build: ./api_service
    environment:
      - NODE_ENV=production
      - PGHOST=db
      - PGPORT=5432
      - PGDATABASE=yyc3_music
      - PGUSER=yanyu
      - PGPASSWORD=${PG_PASSWORD}
    depends_on: [db]
    restart: unless-stopped
  db:
    image: postgres:15
    environment:
      - POSTGRES_DB=yyc3_music
      - POSTGRES_USER=yanyu
      - POSTGRES_PASSWORD=${PG_PASSWORD}
    ports: ["5433:5432"]
    volumes: ["pg_data:/var/lib/postgresql/data"]
    restart: unless-stopped
volumes:
  pg_data:
```

> 生产数据库统一为 **PostgreSQL 15**（本地 `yyc3_music:5433`，NAS Docker `yyc3-music`）。MongoDB 与 SQLite 仅作为遗留调试入口保留。

## 三、Nginx 参考配置

```nginx
server {
  listen 80;
  server_name m98.example.com;

  root /usr/share/nginx/html;
  index index.html;

  gzip on;
  gzip_types text/css application/javascript application/json image/svg+xml;

  # 静态资产长缓存
  location ~* \.(mp3|jpg|jpeg|png|svg|woff2)$ {
    expires 30d;
    add_header Cache-Control "public, immutable";
  }

  location /api/ {
    proxy_pass http://api:4000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
  }

  location / {
    try_files $uri $uri/ /index.html;
  }
}
```

## 四、运行时配置

| 项 | 建议值 |
| -- | ------ |
| Node 进程管理 | PM2 cluster 或容器副本 |
| 日志 | JSON 结构化，输出 stdout |
| 健康检查 | `GET /health` 每 30s |
| 限流 | 全局 100 req/15min，写接口更严格 |
| 超时 | API 10s，静态 30s |
| 时区 | `Asia/Shanghai` |

## 五、监控与告警

| 层级 | 指标 | 工具 |
| ---- | ---- | ---- |
| 基础设施 | CPU / 内存 / 磁盘 | node_exporter |

## 六、备份与恢复

| 数据 | 频率 | 方式 |
| ---- | ---- | ---- |
| PostgreSQL 15 | 每日 | `pg_dump -Fc yyc3_music` + 对象存储 |
| SQLite（遗留） | 每日 | 文件快照 + 校验 |
| 媒体资产 | 变更时 | 版本化对象存储 |
| 配置 | 变更时 | Git 私密仓库 |

恢复演练每季度一次，记录 RTO/RPO。

## 七、发布与回滚

```text
发布：main 合并 → CI 构建 → 镜像打标 vX.Y.Z → 预发验证 → 生产滚动更新
回滚：镜像回退上一 tag → 数据回滚（如需）→ 健康检查 → 通报
```

**回滚判定**：5xx 比例 > 1%、核心接口不可用、P0 缺陷出现。
