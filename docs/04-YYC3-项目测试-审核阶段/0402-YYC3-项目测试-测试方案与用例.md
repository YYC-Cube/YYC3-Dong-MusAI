## 四、边界与异常场景清单

| 用例 ID | 场景 | 输入 | 预期 |
| ------- | ---- | ---- | ---- |
| E-001 | `limit` 超上限 | `?limit=999999` | 返回 400 或钳制为 100 |
| E-002 | `limit` 非法 | `?limit=abc` | 返回 400 |
| E-003 | `page` 为 0 或负 | `?page=0` | 返回 400 或按 1 处理 |
| E-004 | `type` 非法 | `?type=unknown` | 返回空列表而非 500 |
| E-005 | 不存在的作品 ID | `POST /api/music/not-exist/play` | 404 + `success:false` |
| E-006 | 非法 ObjectId | `POST /api/music/123/play` | 404/400，不抛未捕获异常 |
| E-007 | 超大 JSON | 11MB body | 413 Payload Too Large |
| E-008 | 并发播放统计 | 100 并发 POST | 计数准确（无丢失更新） |
| E-009 | 数据库不可用 | 停止 Mongo | 500 + 统一错误结构，不泄露堆栈 |
| E-010 | 音频文件缺失 | 重命名 1 个 mp3 | 播放器提示失败，不白屏 |
| E-011 | 封面缺失 | 删除 1 张封面 | `onError` 回退到默认封面 |
| E-012 | 断网 | DevTools Offline | 展示错误态，可恢复 |

> **重点风险**：E-008 当前实现为“读-改-写”统计（`SELECT stats` → `UPDATE stats`），并发下存在丢失更新，建议改为原子自增（Mongo `$inc` / SQLite `UPDATE ... SET plays = plays + 1` 需先结构化字段）。

## 五、接口测试覆盖建议

### 5.1 接口清单与关键校验点

| 接口 | 方法 | 关键校验 |
| ---- | ---- | -------- |
| `/health` | GET | `status=OK`、`version`、`database` |
| `/api/artist/profile` | GET | `success=true`、`data.name`、`genres` 为数组、`stats` 为对象 |
| `/api/artist/stats` | GET | `totalReleases` 为非负整数、`latestRelease` 可为 null |
| `/api/artist/latest-activity` | GET | `latestReleases` 数组、`socialActivity` 数组 |
| `/api/music/releases` | GET | `pagination` 四字段、`releases` 数组、封面字段存在 |
| `/api/music/featured` | GET | 最多 3 条、按播放量降序 |
| `/api/music/latest` | GET | 有数据 200 / 无数据 404 |
| `/api/music/:id/play` | POST | `plays` 递增、返回值类型为数字 |
| `/api/fans/wall` | GET | 最多 20 条、时间字段可解析 |
| `/api/fans/stats` | GET | 百分比合计为 100 |
| `/api/content/exclusive` | GET | `isLocked` 为布尔、锁定项含 `unlockCondition` |
| `/api/content/blog` | GET | `tags` 数组、`readTime` 数字 |
| `/api/content/events` | GET | `status` 枚举、日期可解析 |

### 5.2 冒烟脚本

```bash
BASE=http://localhost:4000

for path in /health /api/artist/profile /api/artist/stats \
  /api/artist/latest-activity /api/music/releases /api/music/featured \
  /api/fans/wall /api/fans/stats /api/content/exclusive \
  /api/content/blog /api/content/events; do
  code=$(curl -s -o /dev/null -w "%{http_code}" "$BASE$path")
  echo "$code  $path"
done

# 播放统计
ID=$(curl -s "$BASE/api/music/releases" | jq -r '.data.releases[0].id')
curl -s -X POST "$BASE/api/music/$ID/play" | jq .
```

## 八、测试通过标准与失败判定

### 8.1 通过标准

| 层级 | 标准 |
| ---- | ---- |
| 冒烟 | 13 个接口全部 2xx（`/api/music/latest` 允许 404） |
| 功能 | P0 用例 100% 通过，P1 ≥ 95%，P2/P3 ≥ 85% |
| 缺陷 | P0 = 0，P1 ≤ 2 且有规避方案 |
| 覆盖率 | 后端语句覆盖 ≥ 80%，前端核心组件 ≥ 70% |
| 兼容性 | 主流 4 浏览器无阻断性差异 |
| 性能 | 首页 LCP < 2.5s，接口 P95 < 300ms（本地基线） |
| 安全 | 无高危依赖漏洞；密钥不落库；写接口有限流 |

### 8.2 失败判定

| 判定 | 条件 |
| ---- | ---- |
| 阻断 | 服务无法启动、核心链路不可用、数据丢失、密钥泄露 |
| 严重 | P0 用例失败、接口契约不兼容、并发统计错误 |
| 一般 | 非核心功能异常、样式错位、文案错误 |
| 提示 | 体验优化项、非阻断告警 |
